Implementado na infra Storage & Intake · #005
19 de outubro de 2026

Bucket S3 privado na Railway e segredos de produção ativos para intake consentido.

Problema tratado: Para viabilizar upload seguro de faturas reais sem expor documentos publicamente, é necessária infraestrutura de quarentena com chaves de acesso criptografadas no servidor.
  • Provisionamento de bucket privado S3-compatível milet-invoices na infraestrutura Railway (região iad).
  • Cadastro de segredos de ambiente criptografados na Vercel (Produção e Preview) para integração com Gemini, Resend e S3.
  • Isolamento rigoroso entre artefatos acadêmicos de especificação e o código de produto voltado ao usuário final.
  • Fluxo de intake PME do Grupo A ativo com validação, consentimento explícito e triagem por IA com limites claros.
Evidência verificável: Credenciais S3 validadas na Vercel; endpoint POST /v1/intakes operacional com fallback seguro em caso de indisponibilidade.
Transparência & Limites: O upload de documentos reais com OCR direto permanecerá em fase de testes assistidos com revisão humana antes da abertura irrestrita ao público.

Implementado no código Mobile Web · #004
04 de outubro de 2026

A jornada passou a ser instalável e resiliente à perda de rede.

Problema tratado: O layout já era responsivo, mas ainda não existiam manifest, instalação ou um app shell offline verificável.
  • PWA com nome, ícones oficiais, modo standalone e botão de instalação quando o navegador oferece o evento.
  • Service worker armazena somente o shell e as fixtures sintéticas necessárias para abrir a jornada sem rede.
  • Rotas de /api são excluídas explicitamente do cache; indisponibilidade aciona fallback local imediato na interface.
Evidência verificável: Manifest, ícones e política do service worker são testados; a instalação pública é comprovada via artefatos em produção.
Transparência & Limites: PWA não significa aplicativo nativo, distribuição em loja, push ou sincronização de dados reais sem autenticação.

Publicado API Sintética · #003
04 de outubro de 2026

O app ganhou um endpoint público mínimo sem fingir persistência.

Problema tratado: O frontend publicado só conseguia usar a fixture embutida, mesmo já existindo um contrato versionado para o caso sintético.
  • Função Vercel same-origin em /api/v1/cases/CASE-UC-MG-00482, restrita à fixture canônica synthetic_demo_only.
  • O app tenta a API por padrão; se ela não responder, mantém a jornada com fallback local identificado no topo da tela.
  • Contrato, correlação e limites são testados sem banco, secrets, upload ou qualquer dado pessoal.
Evidência verificável: Produção observada com HTTP 200, synthetic_demo_only, correlação preservada e private, no-store.
Transparência & Limites: Este endpoint é stateless e público apenas para demonstração. Não é a API com PostgreSQL, OCR ou cobrança.

Implementado no código Runtime Sintético · #002
04 de outubro de 2026

Do protótipo estático a um runtime implantável — ainda sem chamar isso de produção.

Problema tratado: A jornada navegável não tinha contratos versionados, persistência tenant-scoped nem um caminho reproduzível fora do navegador.
  • API NestJS, OpenAPI 3.1 e JSON Schemas versionados para o caso exclusivamente sintético.
  • Adapters PostgreSQL com contexto de tenant, RLS, auditoria append-only e outbox com retry e DLQ.
  • Imagens OCI non-root para API e worker, configuração fail-fast, CORS por allowlist e logs JSON.
  • O portal consulta a API quando disponível; sem ela, exibe que está usando fixture local.
Evidência verificável: 67 testes automatizados aprovados na esteira local de CI, schemas JSON e contratos versionados.
Transparência & Limites: API, worker e PostgreSQL estão prontos para implantação, operando em ambiente de testes; não há cobrança nem integração de distribuidora ativa.

Limites da versão

O que esta entrega não comprova.

Produto e dados

  • O fluxo PME tenta a função sintética pública e mantém uma fixture local como fallback visível.
  • A função é stateless: não há leitura OCR real, persistência, upload nem faturas reais.
  • Os cálculos são demonstrativos e não validam economia ou recomendação no mercado.

Mercado e operação

  • Não há clientes, pilotos ou tração declarados.
  • Não há fornecedores, parceiros ou integrações confirmados.
  • Não há contratação, assinatura, pagamento ou troca de fornecedor.

Confiança

  • Headers de tenant não são autenticação; OIDC e autorização real ainda faltam.
  • RLS e auditoria append-only foram testadas localmente, não operadas em produção.
  • Dados sintéticos e estados simulados são identificados como tais.

Modelo econômico

  • Sem spread oculto nas transações.
  • Taxas e preços continuam hipóteses até decisão explícita.
  • Posição em ranking não deve ser comprada.
